# Эксплуатация

## Что копировать

- базы PostgreSQL метаданных;
- зашифрованный secret bundle и TLS;
- JSON-экспорты критичных книг вне Git;
- точный commit/tag кода и версии образов.

Для каждой копии хранят дату, версию схемы, размер и checksum. Не реже раза в
квартал делают restore-drill на изолированном хосте.

## Проверка после восстановления

1. Healthcheck UI, API, Auth, UnitedStorage, PostgreSQL, Temporal.
2. Вход viewer и admin.
3. Один ключевой дашборд и каждый тип чарта.
4. Выполнение всех критичных запросов, а не только загрузка HTML.
5. Свежесть DWH, контрольные суммы и права.

## Мониторинг

- доступность контейнеров и HTTP health;
- время ответа ключевых графиков;
- свежесть каждой витрины;
- число ошибок загрузки, несопоставленных MDM и отклонённых адресов;
- возраст последней копии и результат последнего restore-drill.

Технические ошибки не показывают как SQL конечному пользователю. UI показывает
понятный статус, а подробности уходят в админскую очередь.

Минимальная пользовательская страница статуса приведена в `examples/status`.
Она проверяет только безопасные HTTP endpoints и не выдаёт uptime, свежесть или
качество зелёными, пока соответствующий источник мониторинга не подключён.
Историю и инциденты следует подавать серверным API из Zabbix/Grafana/Prometheus,
не встраивая в браузер токены этих систем.
